# 02. 管理端页面级设计

## 1. 页面设计原则

管理端页面优先服务“查找、判断、操作、追踪”。页面级设计必须写清：

- 页面目标。
- 核心字段。
- 查询条件。
- 主操作与行操作。
- 权限码。
- 空态、异常态、加载态。
- 与后端接口的对应关系。

## 2. 用户中心 P0 页面

### 2.1 用户管理

页面目标：维护内部员工账号，控制状态、角色、部门、岗位和登录安全。

布局：

```text
┌──────────────┬────────────────────────────────────┐
│ 部门树        │ 查询：用户名/手机号/状态/角色         │
│              │ Toolbar: 新增用户 / 导入 / 导出       │
│              │ Table: 用户 / 部门 / 角色 / 状态 / 操作 │
└──────────────┴────────────────────────────────────┘
```

关键交互：

- 点击部门树过滤用户列表。
- 新增/编辑使用抽屉，字段包括基本信息、组织信息、角色授权、安全设置。
- 重置密码、解锁账号、强制改密为独立行操作。
- 禁用用户需提示影响：无法登录、Token 失效、API 凭证不受影响需另行处理。

权限码：

| 动作 | 权限码 |
| --- | --- |
| 查询 | `system:user:query` |
| 新增 | `system:user:add` |
| 编辑 | `system:user:update` |
| 删除 | `system:user:delete` |
| 重置密码 | `system:user:reset-password` |
| 解锁 | `system:user:unlock` |
| 强制改密 | `system:user:force-change-password` |

### 2.2 角色管理

页面目标：配置功能权限、数据范围和角色状态。

布局：

```text
┌────────────────┬──────────────────────────────────┐
│ 角色列表         │ Tabs: 基本信息 / 菜单权限 / 数据权限 │
│ 新增角色         │ 权限树 / 数据范围矩阵               │
└────────────────┴──────────────────────────────────┘
```

规则：

- 角色列表选中后右侧加载详情。
- 菜单权限使用树形复选框，支持半选。
- 数据权限支持“本人、本人及下属、本部门、本部门及下级、全部、自定义部门”。
- 修改超级管理员角色需二次确认或禁止。

### 2.3 菜单权限

页面目标：维护后台菜单、按钮权限点和前端路由映射。

字段：

- 菜单名称、类型（目录/菜单/按钮）、父级、排序。
- 路由路径、组件路径、图标、是否显示、是否缓存。
- 权限标识、接口资源标识。

交互：

- 树形表格展示菜单层级。
- 新增子菜单从当前行进入。
- 按钮权限点不在侧边菜单展示，但用于按钮控制。

### 2.4 部门管理与数据权限

页面目标：维护组织结构，为用户归属和数据权限提供基础。

布局：

```text
Tree table: 部门名称 / 负责人 / 排序 / 状态 / 操作
Drawer: 部门名称 / 上级部门 / 负责人 / 排序 / 状态
```

规则：

- 删除部门前必须校验是否有子部门、用户、角色数据范围引用。
- 停用部门后，该部门下用户不应自动停用，但新增用户不可选择停用部门。

## 3. 系统中心 P0 页面

### 3.1 定时任务管理

页面目标：维护系统后台任务，支持暂停、恢复、立即执行和查看日志。

表格列：

- 任务名称、任务组、Cron 表达式、处理器、状态、最近执行时间、操作。

操作：

- 新增、编辑、暂停、恢复、执行一次、查看日志。
- 执行一次必须二次确认。
- Cron 输入应支持下次执行时间预览。

### 3.2 任务执行日志

页面目标：排查任务执行结果。

查询条件：

- 任务名称、任务组、执行状态、时间范围。

详情弹窗：

- 参数、开始时间、结束时间、耗时、异常堆栈。
- 异常堆栈默认折叠，支持复制。

### 3.3 通知公告

页面目标：发布内部通知和客户可见公告。

表格列：

- 标题、类型、发布范围、状态、发布时间、发布人、操作。

编辑抽屉：

- 基本信息：标题、类型、摘要、内容。
- 可见范围：内部角色、部门、客户范围。
- 发布设置：立即发布、定时发布、有效期。

状态流：

`草稿 -> 已发布 -> 已下线`

### 3.4 站点配置

页面目标：维护系统级配置项，支持分组、敏感配置脱敏和变更审计。

字段：

- 配置 Key、配置名称、配置值、分组、是否敏感、备注。

规则：

- 敏感配置默认脱敏展示，查看明文需要权限和审计。
- 修改配置后提示是否需要重启或立即生效。

### 3.5 文件管理

页面目标：管理上传文件、附件、导入模板和导出结果。

能力：

- 上传、下载、预览、删除。
- 展示文件类型、大小、业务归属、上传人、上传时间。
- 删除前说明业务引用影响。

### 3.6 操作日志 / 登录日志

操作日志用于审计业务动作，登录日志用于安全追踪。

操作日志列：

- 操作人、模块、动作、对象、结果、IP、时间。

登录日志列：

- 账号、登录结果、IP、设备、地点、时间、失败原因。

规则：

- 日志不可编辑。
- 失败原因必须可读。
- 敏感参数脱敏。

## 4. 空态与异常态

| 场景 | 文案规则 |
| --- | --- |
| 无数据 | 说明当前筛选无结果，并提供重置筛选 |
| 无权限 | 说明缺少的业务权限，提示联系管理员 |
| 接口失败 | 展示失败原因和重试入口 |
| 保存失败 | 指出具体字段或业务校验原因 |
| 删除失败 | 说明关联数据或状态限制 |

## 5. 原型开发顺序

1. 登录页、主框架、403/404。
2. 用户管理、角色管理、菜单管理、部门管理。
3. 定时任务、任务日志、通知公告、站点配置。
4. 文件管理、操作日志、登录日志。
5. 客商中心和海外仓 OMS 页面。
