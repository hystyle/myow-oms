# 00. 设计系统

## 1. 技术适配原则

| 能力 | MYOW 适配方式 |
| -- | --- |
| Ant Design Vue 表单、表格、抽屉、弹窗 | 使用 Element Plus 或 `packages/ui` 封装组件实现 |
| 主题色、紧凑模式、圆角配置 | 先固定设计令牌，后续再扩展主题切换 |
| 标签页、面包屑、KeepAlive | 管理端优先支持，客户端谨慎使用 |
| 权限指令 `v-privilege` | 使用当前 `usePermission` / 权限码控制按钮与菜单 |
| 设置面板、水印、帮助文档 | 作为 P2 能力，不阻塞 P0 页面 |

## 2. 视觉基调

MYOW 的视觉应体现“物流控制塔 + 财务可信账本”的气质。管理端要沉稳、紧凑、可扫描；客户端要更清晰、友好、可自助。

### 2.1 色彩令牌

| 令牌 | 色值 | 用途 |
| --- | --- | --- |
| `--color-ink` | `#17202A` | 主文字、标题 |
| `--color-graphite` | `#45515F` | 次级文字、表头 |
| `--color-canvas` | `#F6F8FA` | 页面背景 |
| `--color-panel` | `#FFFFFF` | 表格、抽屉、工具面板背景 |
| `--color-line` | `#D8DEE6` | 边框、分割线 |
| `--color-primary` | `#2563EB` | 主操作、链接、选中态 |
| `--color-primary-hover` | `#1D4ED8` | 主操作悬浮 |
| `--color-success` | `#16A34A` | 成功、启用、已完成 |
| `--color-warning` | `#D97706` | 待处理、预警 |
| `--color-danger` | `#DC2626` | 失败、禁用、风险 |
| `--color-info` | `#0891B2` | 信息提示、同步中 |

禁止使用大面积紫蓝渐变、装饰性光斑、营销型 hero 卡片。后台界面不做浮夸视觉装饰。

### 2.2 字体与排版

| 场景 | 建议 |
| --- | --- |
| 中文/英文 UI | 系统默认无衬线字体栈 |
| 数字、编码、单号 | 使用等宽字体或 tabular number |
| 页面标题 | 20px / 28px，600 |
| 面板标题 | 16px / 24px，600 |
| 表格正文 | 13px 或 14px |
| 辅助说明 | 12px，使用次级文字色 |

页面内不要滥用大标题。管理端的标题用于定位当前任务，不承担宣传表达。

### 2.3 圆角、间距、密度

| 令牌 | 值 | 说明 |
| --- | --- | --- |
| `--radius-sm` | 4px | 输入框、标签 |
| `--radius-md` | 6px | 卡片、面板、抽屉内容块 |
| `--space-1` | 4px | 紧邻元素 |
| `--space-2` | 8px | 表单项内部 |
| `--space-3` | 12px | 表格操作、按钮组 |
| `--space-4` | 16px | 面板内边距 |
| `--space-6` | 24px | 页面区块间距 |

管理端默认密度为“中紧凑”：表格行高 42-48px，抽屉表单字段间距 16px，查询区一行优先展示 3-5 个条件。

## 3. 布局系统

### 3.1 管理端布局

采用 Side 布局思想，但固定为更适合运营系统的左侧导航：

```text
┌──────────────┬────────────────────────────────────────┐
│ Sidebar      │ Header: breadcrumb / global action / me │
│ 220px        ├────────────────────────────────────────┤
│ module nav   │ Optional page tabs                      │
│              ├────────────────────────────────────────┤
│              │ Page header                             │
│              │ Filter / Toolbar / Table / Drawer       │
└──────────────┴────────────────────────────────────────┘
```

规则：

- 左侧导航承载一级/二级菜单，支持折叠。
- 顶部显示面包屑、租户/组织切换、消息、用户菜单。
- 标签页可作为 P1 能力，先不阻塞核心业务页面。
- 内容区不使用嵌套卡片；页面区块使用全宽面板或清晰分组。

### 3.2 客户端布局

客户端采用更简单的门户结构：

```text
┌────────────────────────────────────────────────────────┐
│ Top header: logo / workspace / account / support        │
├──────────────┬─────────────────────────────────────────┤
│ Portal nav   │ Workbench / self-service pages           │
│ 200px        │ Clear status, forms, documents, bills    │
└──────────────┴─────────────────────────────────────────┘
```

规则：

- 文案面向客户，不使用内部模块名。
- 页面应解释“我现在能做什么、下一步是什么、异常怎么处理”。
- 客户端权限按客户账号角色控制，不能复用内部员工数据权限表达。

## 4. 组件原则

| 组件 | 使用规则 |
| --- | --- |
| 按钮 | 主按钮每个操作区最多一个；危险操作必须二次确认 |
| 图标 | 工具按钮优先使用图标，并提供 tooltip |
| 表格 | 默认支持分页、排序、列宽稳定、空态、加载态 |
| 抽屉 | 复杂新增/编辑优先使用抽屉，宽度 640-840px |
| 弹窗 | 轻量确认、简单表单、详情预览使用弹窗 |
| 标签 | 状态标签必须颜色稳定，不能只靠颜色表达 |
| 步骤条 | 业务流程页使用，普通 CRUD 不使用 |
| 上传 | 必须说明格式、大小、失败原因和重试入口 |

## 5. 状态色语义

| 状态族 | 颜色 | 示例 |
| --- | --- | --- |
| 正常/启用/完成 | 绿色 | Active、已发布、执行成功 |
| 草稿/待处理/暂停 | 琥珀色 | Draft、待审核、已暂停 |
| 失败/禁用/风险 | 红色 | Failed、冻结、黑名单 |
| 同步/处理中 | 青色 | 同步中、执行中 |
| 归档/过期 | 灰色 | 已关闭、已过期 |

## 6. 文案规则

- 按钮使用动作词：`保存`、`发布`、`暂停`、`重试`、`导出`。
- 错误提示必须指出原因和修复方向。
- 空态必须给出下一步动作，不写泛泛的“暂无数据”。
- 同一动作在按钮、确认框、toast 中保持一致命名。
