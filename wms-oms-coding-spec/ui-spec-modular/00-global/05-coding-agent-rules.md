# 09. Coding Agent 执行规则

## 1. 总原则

coding agent 的任务是基于现有项目和本 ui-spec 实现页面，不是重新设计系统、重建 UI 框架或自行发明业务字段。

## 2. 实施前必须先做的分析

每次实现页面前，必须先输出实施方案，包含：

1. 将要修改 / 新增的文件。
2. 复用的现有组件。
3. 页面对应的 API。
4. 页面权限码。
5. 状态枚举和操作条件。
6. 可能影响旧逻辑的点。
7. 验收清单。

未完成分析前，不允许直接写代码。

## 3. 禁止项

- 禁止新增与现有项目无关的 UI 框架。
- 禁止把管理端和客户端实现成两套完全不同的视觉框架。
- 禁止管理端默认使用深色后台模板；默认必须采用统一浅色 SaaS 风格。
- 禁止绕开 `packages/ui` 或项目已封装组件，除非当前确实没有对应组件。
- 禁止自行发明页面字段、接口路径、枚举值、权限码。
- 禁止把管理端术语展示到客户端。
- 禁止把内部异常、接口异常、任务失败、风险规则命中原因原样展示给客户。
- 禁止在客户端展示内部权限码。
- 禁止用 mock 数据替代真实 API，除非明确标记 `TODO: waiting backend API`。
- 禁止保留旧页面中已废弃字段。
- 禁止新增未在页面清单中的页面。
- 禁止危险操作无二次确认。
- 禁止在页面中硬编码大量业务文案，枚举文案应统一维护。
- 禁止将 ID 字段作为 number 输入处理，编码、单号、ID 默认按 string 处理。

## 4. 前端工程约束

- 管理端与客户端应复用同一套基础布局组件、基础表格组件、状态标签组件和表单组件。
- 页面放在 `src/views` 下，按端和业务域分目录。
- API 请求放在 `src/api` 下，按业务域分文件。
- 类型定义放在页面同级 `types.ts` 或统一类型目录。
- 枚举放在 `src/enums` 或业务域枚举文件。
- 权限判断统一使用当前项目的 `usePermission` / 权限指令。
- 表格编码字段统一支持复制。
- 金额字段统一带币种。
- 重量、尺寸字段统一带单位。
- 时间统一格式 `yyyy-MM-dd HH:mm:ss`。
- 查询重置后必须回到第一页。
- 列表加载中必须保持表头稳定。

## 5. 实现顺序

推荐顺序：

1. API 类型和请求方法。
2. 枚举和状态标签映射。
3. 页面路由和菜单。
4. 查询区。
5. 表格和分页。
6. 工具栏和行操作。
7. 抽屉 / 弹窗 / 详情。
8. 权限控制。
9. 空态、异常态、加载态。
10. 自测和验收清单。

## 6. 页面验收通用清单

每个页面完成后必须检查：

- 管理端与客户端视觉一致：浅色顶部栏、浅色侧边导航、卡片式内容区。
- 路由、菜单、面包屑正确。
- 查询条件顺序与 spec 一致。
- 查询、重置、分页行为正确。
- 表格列、列宽、固定列、复制能力正确。
- 状态标签颜色与语义一致。
- 操作按钮权限控制正确。
- 状态不允许的操作不会误触发。
- 危险操作有二次确认。
- 保存中按钮禁用，避免重复提交。
- 空态有下一步动作。
- 接口失败展示原因和 traceId。
- 客户端没有暴露内部术语和内部错误。
- 页面低于 1200px / 900px 时仍可用。

## 7. 给 coding agent 的启动指令模板

```text
请严格阅读 ui-spec 目录，先不要写代码。

目标：实现【页面名称】。

请先完成：
1. 分析该页面所属端、模块、路由、权限码；
2. 找出现有项目中可复用的组件、API 封装方式、枚举写法；
3. 对照 ui-spec 的页面规格，列出新增/修改文件清单；
4. 说明哪些旧字段或旧逻辑需要删除；
5. 给出实施步骤和验收清单。

确认后再开始编码。编码时禁止自行发明字段、接口、权限码，禁止自建 UI 框架，必须复用项目现有组件体系。
```
