# 02. 双端统一视觉风格规范

## 1. 目标

MYOW 管理端与客户端必须看起来属于同一个产品体系。两端共享同一套浅色产品视觉、设计令牌、布局语言、组件风格和状态语义。

统一不是把两端做成完全一样，而是：

- **视觉一致**：背景、卡片、圆角、边框、按钮、状态标签、字体、间距保持一致。
- **信息密度有差异**：管理端保留更高的数据密度和批量处理能力；客户端保留更强的解释性和自助引导。
- **语言边界清晰**：管理端可展示内部状态、Trace ID、同步日志；客户端必须转换为客户可理解的提示。
- **能力边界清晰**：管理端面向内部运营、客服、财务、技术；客户端面向外部客户、卖家、财务、技术对接人员。

## 2. 总体风格

统一采用 **浅色 SaaS 门户风格**：

```text
Top Header: logo / 当前端标识 / workspace / notice / account
Left Nav: 浅色侧边导航 / 当前菜单浅蓝选中态
Main: 页面标题 / 页面说明 / KPI 卡片 / 查询卡片 / 工具栏 / 表格 / 抽屉
```

不再使用管理端深色侧边栏作为默认风格。管理端和客户端都使用浅色顶部栏与浅色侧边导航。

## 3. 双端一致项

| 项 | 统一规则 |
| --- | --- |
| 页面背景 | 使用 `--color-canvas: #F6F8FA` |
| 内容卡片 | 使用白色面板 `--color-panel: #FFFFFF`，圆角 6-10px |
| 边框 | 使用 `--color-line: #D8DEE6` |
| 主色 | 使用 `--color-primary: #2563EB` |
| 当前菜单 | 浅蓝背景 `#EAF1FF` + 主色文字 |
| 状态标签 | 使用统一状态色，不允许每页自定义 |
| 字体 | 系统默认无衬线字体栈 |
| 页面标题 | 20px / 28px，600 |
| 表格正文 | 13px 或 14px |
| 按钮 | 主按钮每个操作区最多一个 |
| 空态 | 必须说明当前无数据原因和下一步动作 |

## 4. 管理端差异

管理端使用同一套浅色视觉，但需要保留内部运营效率：

- 查询条件可以更密集，一行优先 3-5 个条件。
- 表格列可以更多，但必须保证列宽稳定和横向滚动。
- 支持批量操作、导出、列设置、同步、重试、重新下发。
- 可以展示内部状态、同步状态、异常类型、Trace ID、任务日志。
- 危险操作必须二次确认，并说明影响范围。
- 详情页必须支持操作日志、同步记录、变更记录、关联单据。

管理端页面结构：

```text
Top header
Left nav
Page title + internal description
KPI / Risk cards optional
Query panel
Toolbar
Data table
Drawer / Modal / Detail workspace
```

## 5. 客户端差异

客户端使用同一套浅色视觉，但页面要更清晰、友好、可自助：

- 页面文案面向客户，不使用内部模块名和内部异常码。
- 异常必须说明：发生了什么、是否影响履约、客户是否需要操作。
- 工作台优先展示待办、风险、余额、库存、公告。
- 表格可以比管理端更少列，优先展示客户关心的信息。
- 操作按钮必须围绕客户自助：创建、导入、修改地址、查看轨迹、下载面单、去充值、联系客服。
- 不展示内部权限码、内部部门、内部客服归属、异常堆栈、风险规则命中原因。

客户端页面结构：

```text
Top header
Left nav
Page title + customer-facing explanation
KPI / Reminder cards
Task list / Query panel
Data table or card list
Self-service action entry
Support entry
```

## 6. 文案差异规则

| 类型 | 管理端 | 客户端 |
| --- | --- | --- |
| WMS 下发失败 | WMS 下发失败，可重试或查看同步日志 | 仓库暂未接收该订单，请联系客服确认 |
| 接口超时 | WMS_API_TIMEOUT / Trace ID | 仓库状态正在同步，系统会继续更新 |
| 面单失败 | LABEL_PURCHASE_FAILED | 物流面单暂未生成成功 |
| 风险规则命中 | RISK_RULE_HIT，可查看规则日志 | 订单需要进一步确认 |
| 余额不足 | INSUFFICIENT_BALANCE | 账户余额不足，订单暂无法继续履约 |

## 7. Figma / 原型实现要求

Figma 原型必须体现：

1. 管理端和客户端共享浅色顶部栏、浅色侧边导航和卡片式内容区。
2. 管理端不得默认使用深色控制台侧边栏。
3. 客户端和管理端的状态标签、按钮、输入框、表格样式必须一致。
4. 管理端页面可以更密集，但不能破坏统一风格。
5. 客户端页面可以更解释性，但不能偏营销化。

## 8. Coding Agent 实现要求

coding agent 实现页面时必须遵守：

- 管理端与客户端复用同一套基础布局组件，例如 `AppLayout` / `SideNav` / `TopHeader` / `PageHeader`。
- 通过端类型参数区分管理端和客户端的菜单、文案、权限、数据范围。
- 不允许为管理端和客户端分别创建两套完全不同的视觉框架。
- 不允许管理端继续使用深色后台模板，除非某个项目明确声明需要暗色主题。
- 客户端不得复用管理端内部异常文案。
