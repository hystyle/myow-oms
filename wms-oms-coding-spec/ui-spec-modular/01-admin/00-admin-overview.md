# 01. 管理端 UI/UE 设计

## 1. 目标与边界

管理端服务内部运营、销售、财务、风控、客服和系统管理员。它不是客户门户，也不是营销页面。核心目标是让内部人员高效完成配置、审核、跟踪、纠错和运营管理。管理端视觉必须与客户端保持同一套浅色 SaaS 产品风格，只在信息密度、内部状态和操作能力上体现差异。

管理端必须解决：

- 用户中心：账号、角色、菜单、部门、数据权限、登录安全。
- 系统中心：定时任务、任务日志、通知公告、站点配置、文件、审计日志等平台能力。
- 客商中心、海外仓、头程、财务等业务模块的运营后台。
- 权限与数据可见性：不仅控制能否进入页面，还要控制能看哪些数据、能操作哪些按钮。

## 2. 信息架构

一级菜单按业务域组织，不按数据库或接口包组织。

| 一级菜单 | 定位 | P0/P1 |
| --- | --- | --- |
| 工作台 | 内部运营概览、待办、预警 | P0 |
| 用户中心 | 用户、角色、菜单、部门、数据权限、安全策略 | P0 |
| 系统中心 | 任务、公告、配置、文件、日志、字典 | P0 |
| 客商中心 | 客户/供应商一体档案、联系人、地址、标签、公海、黑名单 | P1 |
| 海外仓 OMS | 商品、入库、库存、出库、退货、VAS、基础数据 | P1 |
| 头程管理 | 头程订单、费用、轨迹、单证 | P2 |
| 财务中心 | 账单、钱包、应收应付、对冲、发票 | P2 |
| 集成中心 | ERP/WMS/TMS/API 凭证、映射、同步日志 | P1 |

## 3. 登录入口

管理端与客户端必须使用不同入口、不同视觉语义、不同登录后初始化流程。

| 项 | 管理端 |
| --- | --- |
| URL | `/admin/login` |
| 登录身份 | 内部员工 |
| 登录凭据 | 用户名/手机号/邮箱 + 密码 + 验证码 |
| 安全能力 | 密码复杂度、错误锁定、强制改密、MFA 预留 |
| 成功后 | 获取用户、菜单、权限码、数据范围、租户策略 |
| 失败后 | 刷新验证码，明确提示账号、密码、验证码、锁定原因 |

管理端登录页面采用“控制台入口”表达：左侧展示系统名称、环境标识、当前版本或安全提示；右侧为登录表单。不要使用客户业务看板，也不要展示外部客户入口。

## 4. 全局框架

### 4.1 主框架结构

```text
┌────────────────────────────────────────────────────────────┐
│ Top header: Logo / 管理端 / Org / Notice / User             │
├──────────────┬─────────────────────────────────────────────┤
│ Light nav    │ Page title / description / primary actions   │
│ Module menu  │ KPI cards / Query panel / Toolbar            │
│              │ Data table / split view / detail workspace   │
└──────────────┴─────────────────────────────────────────────┘
```


### 4.1.1 与客户端统一的视觉规则

管理端必须使用与客户端一致的浅色门户框架：

- 顶部栏为白色，包含产品标识、端类型、组织/租户、通知、用户菜单。
- 左侧导航为浅色背景，当前菜单使用浅蓝选中态。
- 页面背景为浅灰，内容使用白色卡片。
- 查询区、工具栏、表格、状态标签、KPI 卡片、抽屉与弹窗样式与客户端一致。
- 管理端可以更密集，但不能变成另一套深色后台模板。
- 深色侧边栏只允许作为可选主题，不作为默认实现。

### 4.2 导航规则

- 左侧菜单最多展示三级。超过三级应在页面内部用 Tabs 或分栏承载。左侧菜单默认使用浅色背景。
- 一级业务域 / 大目录必须支持折叠和展开，避免菜单过多时挤满侧栏。
- 当前路由所在的大目录默认自动展开，其他大目录可保持收起。
- 用户手动展开 / 收起的大目录状态应在当前会话内保持。
- 大目录收起后必须保留目录标题和展开指示，不能让用户失去业务域入口。
- 面包屑显示模块路径，支持回到上级列表。
- 权限不足的菜单不展示；直接访问无权限路由进入 403。
- 当前菜单必须高亮，刷新后保持当前路由状态。

### 4.3 页头规则

页头包含：

- 页面名称：使用业务名称，如“用户管理”“通知公告”。
- 简短说明：说明页面能做什么，不写营销话术。
- 主操作：新增、导入、同步等，最多一个主按钮。
- 辅助操作：刷新、导出、列设置等放右侧图标按钮。

## 5. 通用页面范式

### 5.1 列表页

```text
Page header
Query panel: keyword / status / owner / time range
Toolbar: primary action / batch action / export / column setting
Table: stable columns / row actions / status tags
Pagination
Drawer or modal
```

规则：

- 查询区默认展开关键条件，高级条件可折叠。
- 表格列宽稳定，编码、单号、状态、时间、操作列位置固定。
- 操作列常用顺序：详情、编辑、启用/停用、删除。
- 危险动作必须二次确认，并说明影响范围。

### 5.2 表单页

复杂表单优先使用抽屉：

- 640px：简单编辑。
- 760px：包含权限、树选择、多组字段。
- 840px：多段配置、包含表格子项。

字段分组：

- 基本信息
- 业务配置
- 权限/可见性
- 审计信息

### 5.3 详情页

详情页不是只读表单，应支持业务追踪：

- 顶部摘要：名称、编码、状态、负责人、关键时间。
- 主信息区：字段分组展示。
- 右侧或底部：操作日志、变更记录、同步记录、关联单据。
- 有风险状态时必须展示原因和解除路径。

## 6. 权限与数据可见性

| 控制层 | 说明 |
| --- | --- |
| 菜单权限 | 决定是否出现菜单和路由 |
| 按钮权限 | 决定页面内动作是否可见 |
| 数据权限 | 决定列表和详情能看哪些记录 |
| 字段权限 | 决定敏感字段是否脱敏或隐藏 |
| 操作条件 | 决定当前状态是否允许该动作 |

销售客户数据隔离、客户公海、黑名单等业务必须同时使用数据权限和字段脱敏，不能仅靠按钮权限。

## 7. 接口驱动规则

后端接口实现必须添加 springdoc 注解：

- `@Operation(summary = "...", description = "...")`
- DTO 字段使用 `@Schema(description = "...", example = "...")`
- 分页、创建、更新、状态变更接口说明必须明确业务影响。
- 权限码应在接口说明或模块文档中保持一致。

前端生成页面时依赖：

- API 路径与方法。
- 请求/响应 DTO。
- 字段说明、是否必填、枚举含义。
- 权限码。
- 错误码与错误提示。
